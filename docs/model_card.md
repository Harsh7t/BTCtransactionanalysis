# Model card — BTC-FUSION detector

**Version** artifacts/v1 · feature version 7 · seed 20260826 · 132 features ·
42,245 training entities · backend `sklearn_histgb` · git `dab45c0`

## Intended use

Generating **prioritised, explainable investigative leads** for a human analyst on an
air-gapped workstation. The output is a ranked queue of case files, each carrying its
evidence, its reasoning, and its confidence.

## Out-of-scope use

- **This is not evidence.** An alert is a hypothesis with a confidence attached. It is a
  starting point for an investigation, never a finding.
- **Not for automated action.** Nothing here should freeze an account, block a
  transaction, or be actioned without a human reading the case file.
- **Not a real-world detection rate.** Every figure is measured on synthetic data we
  generated. See `docs/generator_parameters.md`.
- **Not attribution-grade identification.** A network attribution at confidence 0.91 is a
  lead about an *address*, not an identification of a person.

## Training data

Synthetic, generated by `btcfusion/generator/` from a fixed seed. 8 actor archetypes,
6 laundering typologies (2 held out entirely). Entity labels are recovered by mapping
resolved clusters to ground truth by majority address, at mean purity 0.9958.

Splits are entity-grouped and temporally forward; calibration uses its own fold. All three
rules are enforced by assertions that raise, not warn.

## Known failure modes

From the measured failure gallery in `metrics.json`:

- **Legitimate pass-through wallets flagged as mules.** Short-lived wallets that receive
  one chunk and forward it are structurally near-identical to laundering mules.
  Separating them needs counterparty reputation this system deliberately does not model.
- **Exchange batch payouts flagged as fan-out.** A legitimate batch payout across many
  outputs is indistinguishable from a laundering fan-out at the topology level.
- **Purely temporal typologies missed.** `dormancy_burst`'s signature is a long gap then a
  burst; the topological features the model leans on cannot see it.
- **Attribution inverts below ~10% observation coverage** — worse than guessing.

## Ethical considerations

This is a surveillance tool built for a signals-intelligence context. Three design choices
follow from that:

- **Abstention is a feature.** Where every candidate address is shared infrastructure the
  engine suppresses attribution rather than reporting a misleading number. 195 abstentions
  in the evaluated run.
- **Victims are never labelled illicit.** Being paid by a criminal does not make you one,
  and a generator that labelled payers illicit would teach the model to flag bystanders.
- **Analyst feedback re-ranks presentation only.** Verdicts demote or promote the next
  run's queue; they never retrain the model. Retraining on analyst clicks without a
  controlled evaluation is how a triage tool quietly learns one person's habits.
